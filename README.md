## 기능 구성

### 1. 회원가입

사용자는 아이디, 비밀번호, 이름, 전화번호를 입력하여 회원가입을 진행한다.

#### 입력 정보

| 필드명 | C 타입 | 필수 여부 | 설명 |
|:---|:---|:---:|:---|
| `user_id` | `char[]` | 필수 | 사용자를 고유하게 식별하는 ID |
| `password` | `char[]` | 필수 | 사용자 계정의 비밀번호 |
| `name` | `char[]` | 필수 | 사용자 이름 또는 닉네임 |
| `mdn` | `char[]` | 필수 | 사용자의 전화번호(Mobile Directory Number) |

#### 처리 절차

1. 필수 입력값의 존재 여부와 형식을 검증한다.
2. `user_id`를 기준으로 중복 가입 여부를 확인한다.
3. `mdn`을 기준으로 기존 가입 여부를 확인한다.
4. 다음 조건에 해당하면 회원가입을 제한한다.
   - 동일한 `user_id`가 이미 존재하는 경우
   - 동일한 `mdn`이 이미 등록된 경우
5. 검증이 완료되면 사용자 정보를 저장하고 가입 처리를 완료한다.

> `user_id`와 `mdn`은 사용자별로 고유한 값이어야 한다.

---

### 2. 로그인

사용자는 아이디와 비밀번호를 입력하여 로그인한다.  
로그인에 성공하면 API 인증에 사용할 access token과 refresh token을 발급한다.

#### 입력 정보

| 필드명 | C 타입 | 필수 여부 | 설명 |
|:---|:---|:---:|:---|
| `user_id` | `char[]` | 필수 | 사용자를 고유하게 식별하는 ID |
| `password` | `char[]` | 필수 | 사용자 계정의 비밀번호 |

#### 처리 절차

1. `user_id`와 `password`를 입력받는다.
2. `user_id`를 기준으로 사용자 정보를 조회한다.
3. 사용자 존재 여부와 비밀번호 일치 여부를 확인한다.
4. 인증에 실패하면 로그인 실패 응답을 반환한다.
5. 인증에 성공하면 access token과 refresh token을 생성한다.
6. 생성된 토큰, 사용자 정보 및 만료 시간을 Redis에 저장한다.
7. 클라이언트에 access token과 refresh token을 반환한다.

#### 로그인 실패 조건

- `user_id`에 해당하는 사용자가 존재하지 않는 경우
- 입력한 비밀번호가 저장된 비밀번호와 일치하지 않는 경우

### 3. 토큰 관리

#### 토큰 종류

| 토큰 | 기본 만료 시간 | 용도 |
|:---|:---:|:---|
| Access Token | 30분 | 일반 API 요청 인증 |
| Refresh Token | 14일 | Access Token 재발급 |

토큰 만료 시간은 코드에 직접 고정하지 않고 Kubernetes `ConfigMap`을 통해 설정한다.

#### 생성 방식

Access Token과 Refresh Token은 OpenSSL에서 제공하는 `RAND_bytes()`를 사용하여 생성한다.

- 암호학적으로 안전한 난수로 구성한다.
- 두 토큰은 서로 다른 값으로 생성한다.
- 일반적인 `rand()` 함수는 결과를 예측할 수 있으므로 인증 토큰 생성에 사용하지 않는다.
- 토큰은 JWT가 아닌 고유한 랜덤 문자열 방식으로 관리한다.

#### OpenSSL 라이브러리

빌드 시 OpenSSL crypto 라이브러리를 연결한다.

```bash
-lcrypto
```

`-lcrypto`는 JWT 서명을 위한 것이 아니라 다음 기능을 사용하기 위해 추가한다.

- 안전한 랜덤 토큰 생성
- 토큰의 SHA-256 해시 처리
- 비밀번호 해시 관련 보조 처리

#### Redis 저장 정보

로그인에 성공하면 Redis에 다음 정보를 저장한다.

| 저장 정보 | 설명 |
|:---|:---|
| 토큰 | Access Token 또는 Refresh Token |
| `user_id` | 토큰을 발급받은 사용자 |
| 토큰 종류 | Access 또는 Refresh |
| 만료 시간 | 토큰이 유효한 기간 |

> Redis의 TTL 기능을 사용하여 토큰 만료 시간을 관리한다.

### 4. 연락처

연락처 기능은 전화번호인 `mdn`을 이용해 가입된 사용자를 검색하고, 검색된 사용자를 자신의 친구 목록에 추가하는 기능이다.

친구 관계는 기본적으로 **단방향**으로 관리한다.

예를 들어 사용자 A가 사용자 B를 친구로 추가하더라도 사용자 B의 친구 목록에 사용자 A가 자동으로 추가되지는 않는다.

#### 연락처 정보

| 필드명 | C 타입 | 필수 여부 | 설명 |
|:---|:---|:---:|:---|
| `user_id` | `char[16]` | 필수 | 친구를 고유하게 식별하는 ID |
| `name` | `char[16]` | 필수 | 친구의 이름 또는 닉네임 |
| `mdn` | `char[16]` | 필수 | 친구의 전화번호 |

#### 처리 절차

1. `Authorization` 헤더에서 Access Token을 추출한다.
2. Redis에서 Access Token을 조회한다.
3. 토큰이 유효하면 요청자의 `user_id`를 확인한다.
4. 요청에 `mdn` 파라미터가 존재하는지 확인한다.
5. `mdn` 형식이 유효한지 검증한다.
6. MDN 인덱스를 조회하여 가입된 사용자를 검색한다.
7. 사용자가 존재하면 다음 정보를 반환한다.
   - `user_id`
   - `name`
   - `mdn`
   - `is_friend`
8. 검색된 사용자가 요청자 자신인지 확인한다.
9. 검색된 사용자가 이미 친구로 등록되어 있는지 확인한다.

#### `is_friend` 값

| 값 | 의미 |
|:---:|:---|
| `true` | 이미 친구로 등록된 사용자 |
| `false` | 친구로 등록되지 않은 사용자 |

#### 친구 추가 제한 조건

다음 조건에 해당하면 친구 추가를 제한한다.

- 검색된 MDN이 요청자 자신의 MDN인 경우
- 검색된 사용자가 이미 친구로 등록된 경우
- 해당 MDN으로 가입된 사용자가 존재하지 않는 경우

> 자신의 MDN을 검색한 경우 사용자 정보는 반환하지만, 친구 추가는 허용하지 않는다.
